## 1. 观察期入院（OBSERVATION）是否排除

**背景**：
- 很多病人先以"观察"身份住院，后来转为正式住院。Medicare 的 3 天住院规则（C1，42 CFR 409.30(a)）只算正式住院的午夜数，所以这些病人正是 C1 判定的边界难例。
- 附录 A：去 SNF 的 Medicare 住院里，`OBSERVATION ADMIT` 有 9,696 例，占 23%（已复现：9,696，22.9%）。

**Hui Li**：排除，两道条件。
```sql
-- origin/snf-criterion-cards:src/snf_pa/data/cohort.py L60
and a.admission_type not ilike '%OBSERVATION%'
-- L49: obs_unit = transfers 里 careunit = 'Observation' 的住院；L80 eligible_filter(): ... and not had_observation_unit
```

**cfeng**：
- 主样本同样排除：`origin/cfeng:src/snf_pa/data/cohort.py` L94–95，`admission_type not ilike '%OBSERVATION%'` 和 `hadm_id not in (select hadm_id from obs_unit)`。
- 另外在补充样本里专门抽了 20 例：`build_supplement.py` L30，`"obs_to_inpatient": ("observation and midnights >= 3", {SNF: 20})`。

**我们**：**不排除**。观察期入院留在候选池里，作为抽样的边界分层之一（"先观察后住院"）。谁定的：设计 3.2（"同时记录的分层变量：是否先观察后住院"）、附录 A（"不能排除"）、10.1 分层。

**对结果的影响**：
- 排除后，评估集里几乎没有 C1 难例。C1 规则引擎和"技术性不符"结论（`TECHNICAL_NOT_MET`）得不到检验。
- 指标会偏乐观：剩下的都是住院时间明确、更容易判的病例。

**建议**：队列层面不排除，改成分层变量。cfeng 补充样本的做法方向一致，但放在主样本之外，主样本本身的分布仍然缺这类病例。

## 2. 住院午夜数 ≥3 是否作为纳入条件

**背景**：
- 午夜数正是 C1 要判定的内容。设计里 C1 由规则引擎从 POE "Admit to inpatient" 医嘱时间起算（设计 3.4、6.2）。不足 3 午夜的病例要保留，系统应判 `TECHNICAL_NOT_MET` 或 `INSUFFICIENT`。
- 附录 A：去 SNF 但按入院时间算不足 3 午夜的有 3,484 例，其中 940 例（27%）在 30 天内有合格的前序住院，也就是仍可能符合 C1。

**Hui Li**：作为纳入条件，按入院、出院日期差计算。
```sql
-- origin/snf-criterion-cards:src/snf_pa/data/cohort.py L56, L75
date_diff('day', a.admittime::date, a.dischtime::date) as inpatient_midnights
...
where b.age_at_admit >= {C.MIN_AGE} and b.inpatient_midnights >= {C.MIN_MIDNIGHTS}
```

**cfeng**：
- 主样本同样作为纳入条件，同样的日期差算法（`cohort.py` L55、L93）。
- 补充样本里抽了不足 3 午夜的 20 例：`build_supplement.py` L28–29，有 / 无前序住院各 10 例。

**我们**：
- **不作为纳入条件**。候选池里只记录按入院时间算的午夜数，作为抽样的边界分层（"不足 3 午夜"）。
- C1 本身留到第 ④ 步，由规则引擎按住院医嘱计算。
- 谁定的：设计 3.2、6.2、10.1。

**对结果的影响**：
- 同第 1 条，C1 和 `TECHNICAL_NOT_MET` 得不到检验。
- 另外，按日期差算的午夜数会高估：附录 A 里按入院时间 ≥3 午夜的有 38,828 例，按住院医嘱只有 37,337 例，约 3.8% 被高估。用它做纳入条件，会混进实际不满足 C1 的病例。

## 3. 出院去向：对照组是否包含 REHAB（IRF）

**背景**：
- 对照组用来提供"不去 SNF"的病例，例如住院 ≥3 午夜却回家的难例，以及 A0 基线的负例。
- REHAB（住院康复机构，IRF）的病人往往同样需要每日 skilled 康复，是最难和 SNF 区分的一组。附录 A：PT 会诊在 REHAB 中出现率 97%，SNF 中 89%。

**Hui Li**：SNF / HHC / HOME，没有 REHAB。`config.py` L19–23，`LOCATION_QUOTAS = {"SKILLED NURSING FACILITY": 30, "HOME HEALTH CARE": 18, "HOME": 12}`。

**cfeng**：
- 主样本同 Hui Li（`config.py` L22–25）。
- 补充样本里有 REHAB 40 例：`build_supplement.py` L33，`"irf": ("not observation and midnights >= 3", {REHAB: 40})`。

**我们**：**SNF、HHC、HOME、REHAB 四组都进候选池**。谁定的：设计 3.2。

**对结果的影响**：
- 没有 REHAB，就测不出系统能否区分"需要 SNF"和"需要更高强度康复"。
- silver 指标（按去向分组的结论分布）也少了一组对照。

## 4. 入院年份限制

**背景**：
- 出院小结在后期年份覆盖率很低（2020–22 年为 0）。
- 早期年份没有 POE 住院医嘱：附录 A 写"2013 年后约 99% 有"。
- MIMIC 的日期整体平移过，真实年份只能从 `anchor_year_group`（3 年一组）推算，有 ±2 年误差。

**Hui Li**：不限年份。`anchor_year_group` 没用到；样本的 `admittime` 是平移后的 2110–2206 年。

**cfeng**：不限年份。`cohort.py` L90–96 和 `build_supplement.py` L135 都没有年份条件。

**我们**：
- 限定 2011–2018，用**严格规则**：真实年份一定落在 2011–2018 内。条件是"组起点 + 年份偏移 ≥ 2011"且"组终点 + 年份偏移 ≤ 2018"，其中年份偏移 = `year(admittime) − anchor_year`。
- 谁定的：设计 3.2 规定 2011–2018；严格规则由用户在 2026-11-08 选定。

**依据**（实测，Medicare、≥65、存活、有出院小结，住院数 / 病人数）：

| 规则 | SNF | HHC | HOME | REHAB |
|---|---|---|---|---|
| 不限年份（队友） | 30,613 / 19,444 | 34,157 / 20,250 | 32,558 / 20,450 | 5,501 / 4,711 |
| 严格 2011–2018（我们） | 15,795 / 10,483 | 17,308 / 10,937 | 16,335 / 11,053 | 2,657 / 2,297 |

**对结果的影响**：
- 不限年份会混进 2008–2010 年的病例。那几年很多病例没有 POE 住院医嘱，C1 只能退回入院时间，最多判到 `INSUFFICIENT`。
- 也会混进 2019 年以后的病例，那时出院小结的写法和覆盖都不同。
- 规模减半，但仍远超抽样需要。

## 6. dev / test 怎么划分

**背景**：
- 同一个病人的多次住院如果分别落在 dev 和 test，病历风格和病史会同时出现在两边，test 就不干净（设计 3.2）。
- test 一旦冻结就不能改（CLAUDE.md 硬规则 3）。

**Hui Li**：
- 先抽样，再在每个格子（类别 × 去向）里按 hash 排名，排名 % 5 ∈ {1, 2} 的进 test。代码：`origin/snf-criterion-cards:src/snf_pa/data/cohort.py` L138，`case when r.rn % {C.TEST_MODULUS} in ({test_pos}) then 'test' else 'dev' end`。
- 不跨 split 是靠"每人只取一次住院"保证的（L113–117）。
- 结果：dev 171 / test 129。

**cfeng**：
- 同样是先抽样、再在格子里分。
- `build_sample.py` L41–43 把排名靠后的 40% 分进 test，但 `config.py` L27–29 的注释写的是 `rank % 5 in (1, 2)`，两处不一致。
- 划分只存成样本表里的一列，没有独立的划分文件。

**我们**：
- **先按 `subject_id` 划分**：对候选池里的全部病人，按 `sha256(salt + subject_id)` 分成 50 / 50，写成 `data/splits/subjects.csv`，由用户冻结。
- 然后在 dev 病人里抽 100 例、在 test 病人里抽 200 例。
- 谁定的：设计 3.2 和 10.1 规定"先划分再抽样"；50 / 50 由用户在 2026-11-08 选定。

**对结果的影响**：
- 先抽样再划分时，划分依赖抽样结果：改一次抽样，test 的病人就变了，很难保证 test 没被"看过"。
- 先按病人划分并冻结，之后无论怎么调整抽样，test 病人都不会变。

## 8. 临床场景怎么判定：只看第一诊断，还是看全部诊断加实际服务

**背景**：
- 分层抽样要给每个病例一个临床场景（设计 10.1：骨科术后、卒中、内科病后体能下降、心衰、伤口 / 静脉用药），保证评估集覆盖各类病人；分组报告指标时也按场景。
- 这个标签**不进入审核流程**，不会改变任何一个病例的批准或拒绝。Medicare SNF 覆盖标准（42 CFR 409.31–409.35）看的是需要什么 skilled 服务、是否每日、是否只能在 SNF 提供，不看诊断；设计 5.3 还要求 critic 检查"凭诊断推定"。
- 但它决定评估集里有哪些病人。分错类的代价是评估集缺少某类难例，指标显得比实际好。
- 第一诊断（主诊断）在编码规则里的定义是"经检查后确定的、导致这次住院的主要原因"，既不是"最重的病"，也不是"为什么需要 SNF"。

**Hui Li**：只看第一诊断（`seq_num = 1`），关节置换另按手术码。
```sql
-- origin/snf-criterion-cards:src/snf_pa/data/cohort.py L69-70
left join read_csv_auto('{h}/diagnoses_icd.csv.gz', types={{'icd_code':'VARCHAR'}}) d
       on d.hadm_id = b.hadm_id and d.seq_num = 1
```
匹配规则是 `CATEGORY_CASE`（L13–25），匹配到第一个就停；匹配不上的 `category is null`，不进样本。

**cfeng**：同样只看第一诊断。
```sql
-- origin/cfeng:src/snf_pa/data/cohort.py L60-66
dx1 as (
  select d.hadm_id, d.icd_code as first_dx_code, ... {DX_CATEGORY} as dx_category
  ...
  where d.seq_num = 1
),
```
L79–81 先认髋骨折，再认关节置换，再用第一诊断类别；L99 `where category is not null`，匹配不上的不进样本。

**我们**：
- 最初的草案也只看第一诊断（直接沿用了队友的做法，设计 10.1 没规定怎么判定）。用户追问后实测，发现会漏很多（见依据），**已放弃**。
- **新方案**（用户同意，已写入设计 v8 第 10.1 节，见 `plan/decision_log.md` D-003），分两个维度：
  1. **住院原因**：第一诊断 + 手术码（关节置换）。回答"这次为什么住院"。心衰只按这一维判。
  2. **SNF 需求标签**（一个病例可以有多个），回答"为什么可能需要 SNF"：
     - 任意诊断位置出现、且与护理需求直接相关的诊断：髋骨折、急性卒中、压疮、痴呆、帕金森、体能下降；
     - 实际接受的服务（处方表、医嘱表）：静脉抗生素、伤口护理医嘱、PT/OT 会诊。
- **抽样**时每个病例仍只落一个格子，否则名额会重复计算。主场景按优先级取：骨科 > 卒中 > 伤口 / 静脉用药 > 心衰 > 内科体能下降，其中"伤口 / 静脉用药"按需求标签判。
- **报告**时每个标签单独统计，一个病例属于几类就出现在几组里。
- 实现：需求标签定义在 `knowledge/needs.yaml` v1（服务类按医嘱 / 处方，在 T_pa 前；状况类按任意位置诊断，只用于抽样和报告），打标签在 `src/snf_pa/needs.py`，场景在 `research/scenarios.py`，抽样在 `research/sample.py`。结果见 `reports/step2_cohort_subset.md` 第 7 节。
- 谁定的：用户提出"不应只看第一诊断""符合的每一类都要考虑"；具体方案由我起草，待用户确认。

**依据**（2026-11-08 实测，候选池 52,095 例住院，每例诊断数中位 15 个）：

| 情况 | 第一诊断就是它（去 SNF 的） | 任意位置有它（去 SNF 的） | 只看第一诊断漏掉 |
|---|---|---|---|
| 压疮 | 24 | 857 | 97% |
| 痴呆 | 79 | 3,002 | 97% |
| 帕金森 | 27 | 464 | 94% |
| 肺炎 | 365 | 1,592 | 77% |
| 急性卒中 | 395 | 542 | 27% |
| 脓毒症 | 1,022 | 1,386 | 26% |
| 髋骨折 | 709 | 771 | 8% |
| 心衰 | 623 | 5,390 | —（见下） |

- 典型漏掉的情况：
  - 因尿路感染或肺炎住院，但有压疮需要每日伤口护理；
  - 因跌倒住院，但有痴呆、帕金森或陈旧卒中，回不了家；
  - 手术住院后体能下降或伤口感染；
  - 按编码规则，"肺炎引起脓毒症"的主诊断写脓毒症，肺炎反而成了次要诊断。
- 反过来，"任意位置都算"也不行：任意位置出现心衰的有 15,136 例（占候选池 29%），多数只是记录在案的慢性病。所以心衰只认第一诊断。

**对结果的影响**：
- 只看第一诊断时，压疮、痴呆、帕金森这类最典型的 SNF 病人会被分进别的类，甚至进"不抽样"那一组。评估集里这类难例偏少，伤口护理、认知障碍相关的判定得不到检验。
- 两位队友的样本还有一层：第一诊断不在 5 个类别里的病例直接不进样本，所以这些病人完全不在评估集里。

**建议 / 待讨论**：
- 三人统一用"住院原因 + 需求标签"两维分类。
- 需求标签的具体阈值（例如静脉抗生素用几天算）三人一起定。

## 9. 场景码表：两位队友的码表不一致，我们怎么选

**背景**：第 8 条的"住院原因"仍要用诊断码表。两位队友的码表有差异。

**Hui Li**（`origin/snf-criterion-cards:src/snf_pa/data/cohort.py` L13–25、L43–47）：
- 卒中只有缺血性（I63 / 434）；
- 心衰只有 I50 / 428；
- 关节置换含 ICD-9 81.55（膝关节翻修）。

**cfeng**（`origin/cfeng:src/snf_pa/data/cohort.py` L9–30）：
- 卒中加了出血性卒中（I61 / 431）和 433.x1、436；
- 心衰加了高血压性心脏病伴心衰（I11.0、I13.0、I13.2 / 402.x1、404.x1、404.x3）；
- 关节置换不含 81.55。

**我们**（`research/scenarios.py`，草案）：
- 卒中、心衰用 cfeng 的码表；
- 关节置换跟 cfeng，不含 81.55；
- 谁定的：实现时的判断，待用户确认场景定义时一起确认。

**依据**：
- 出血性卒中和缺血性卒中一样会导致偏瘫和康复需求；
- 高血压性心脏病伴心衰在 ICD-10 里要求用 I11.0 / I13.x 作主码、I50 作附加码，只用 I50 会漏掉这些病人；
- 81.55 是翻修术，和初次置换的康复路径不同。

**对结果的影响**：用 Hui Li 的码表，卒中和心衰场景会少一部分病人。影响未精确评估。

## 10. 是否按出院小结长度过滤

**背景**：病例必须有出院小结（设计 3.2）。是否还要求小结有一定长度？

**Hui Li**：只要求有出院小结（`cohort.py` L67，`has_note`），不限长度。

**cfeng**：要求出院小结至少 500 个字符。
```sql
-- origin/cfeng:src/snf_pa/data/cohort.py L87
join notes_index ni on ni.hadm_id = adm.hadm_id and ni.n_chars >= 500
```

**我们**：只要求有出院小结，不限长度（`src/snf_pa/adapters/cohort.py`，`has_note`）。谁定的：设计 3.2 只写"有出院小结"。

**对结果的影响**：
- 很短的出院小结证据很少，系统更可能判 `INSUFFICIENT` / `PEND_INFO`。按设计（硬规则 4"缺失就是缺失"），这正是应该测到的情况。
- 过滤掉会让指标偏乐观。
- 短小结的数量未统计，影响未评估。

**待讨论**：如果担心空白或模板化的小结，可以改为分层变量或单独报告，而不是排除。

## 11. "每人一次住院"在哪一步做

**背景**：同一个病人的多次住院不能同时出现在样本里（病历风格、病史重复）。可以在建候选池时就只留一次，也可以在抽样时再选。

**Hui Li**：候选池保留全部住院，抽样时每人选一次（`cohort.py` L113–117，`row_number() over (partition by subject_id ...)`）。

**cfeng**：建候选池时就每人只留一次（`cohort.py` L100–101，`qualify row_number() over (partition by subject_id ...) = 1`）。

**我们**：候选池保留全部住院（52,095 例 / 26,661 人），按病人划分 dev / test，抽样时每人最多选一次。谁定的：实现时的判断。

**依据**：
- 第 ③ / ④ 步要看"30 天内是否有合格的前序住院"（C1，设计 6.2），候选池需要知道同一病人的其他住院。Parquet 子集也保留了这些病人的全部住院。
- 划分按病人做，同一病人的所有住院自然在同一边。

**对结果的影响**：
- 对抽样结果本身无大影响（三种做法都保证一人一次）。
- cfeng 在候选池阶段先按 hash 随机留一次住院，之后的分层就只能在这一次住院里找。病人的另一次住院可能正好是边界病例（例如观察期入院），这样就被丢掉了。影响未评估。
